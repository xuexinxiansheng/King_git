# Kingdom Rush 修改器 · 代码说明

三个文件跑在三个位置，通信全靠 `%LOCALAPPDATA%\KR_Trainer\` 下的文本文件：

| 文件 | 运行位置 | 职责 |
|---|---|---|
| `src/trainer.py` | 本机（Python/PySide6） | 界面 + 注入器 |
| `src/krbridge.dll` | 游戏进程内（C） | 注入后把 Lua 载荷塞进游戏 |
| `src/payload.lua` | 游戏内（LuaJIT） | 每 0.1s 读配置、改数值、回写状态 |

```
trainer.py ──写──► state.txt ──► payload.lua ──► 改游戏数值
trainer.py ◄─读── status.txt / towers.txt ◄── payload.lua
```

| 文件 | 方向 | 内容 |
|---|---|---|
| `state.txt` | 界面→游戏 | `key=value`（开关、数值、`tw_<系>_<spd/dmg/rng>` 塔倍数） |
| `status.txt` | 游戏→界面 | 状态读数（gold/lives/wave/level/state） |
| `towers.txt` | 游戏→界面 | 塔参数清单 `模板|中文名|类型|等级|造价|cd|伤害|射程|弹药|family` |
| `cmd.txt` / `out.txt` | 调试 | 向游戏内执行任意 Lua 并回显 |

## trainer.py

- 注入：`ctypes` 调 Win32（`OpenProcess` → `VirtualAllocEx` → `CreateRemoteThread(LoadLibraryW)`），无第三方库
- 自绘组件：`NeoCard`（卡片）、`WinButton`、`TitleBar`、`CheckBox`、`FuncRow`、`TowerCell/TowerRow`、`ShadowWrap`、`InfoDialog`
- 布局：标题栏 → 路径/状态 → 操作按钮 → **01 修改设置**（分页 + `QStackedWidget`：全局设置/防御塔/英雄与友军）→ **02 运行日志**；窗口高度按 `sizeHint()` 自适应
- `load_towers()`：优先读 `towers.txt`，读不到用内置 `TOWERS_BUILTIN`（22 行），打开界面立刻有表
- `rebuild_towers()`：按 `family` 聚合成 4 行 `TowerRow`，保留用户已勾选状态
- `write_state()`：把开关/数值写成 `state.txt`，是界面→游戏唯一下行通道；倍数未勾选写 `0`

## krbridge.c

IAT Hook `lua51.dll` 的 `lua_gettop` / `lua_pcall` / `luaL_loadbuffer`（三个都 hook，谁先触发谁执行载荷），
`InterlockedCompareExchange` 保证只跑一次，之后还原。改功能一般只动 `payload.lua`，无需重编 DLL。

## payload.lua

### 游戏数据模型（逆向结论，勿凭猜）

| 位置 | 含义 |
|---|---|
| `e.template_name` | 塔型标识，如 `tower_archer_1` |
| `e.tower.type / level / price` | 系别 / 等级 / 造价 |
| `e.attacks.range` | 塔总射程 |
| `e.attacks.list[i].cooldown` | 攻击间隔（越小越快） |
| `e.attacks.list[i].range` / `.range_base` | **每种攻击模式自带射程**（大贝莎：炸弹 199 / 集束 180 / 导弹 base 199） |
| `e.attacks.list[i].max_track_distance` | 弹道跟踪半径（默认 128） |
| `e.attacks.list[i].bullet` | 弹药模板名（字符串），如 `arrow_1` / `bomb` |
| `edb.entities[弹药].bullet.damage_min/max` | 普通伤害 |
| `edb.entities[弹药].bounce_damage_min/max` | 连锁闪电（特斯拉） |
| `edb.entities[弹药].bullet.mod → *.dps.damage_*` | 持续伤害（奥术） |
| `edb.entities[弹药].bullet.max_track_distance` | 炮弹跟踪半径（默认 64） |
| `e.barrack.rally_range` | 兵营驻扎半径 |
| `e.barrack.max_soldiers` | 兵营士兵数（默认 3，精灵塔 4）；`tower_barrack.update` 每 tick 按它补齐士兵 |
| `e.barrack.soldiers[i]` / `.soldier_type` | 士兵实体数组 / 士兵模板名（补兵时写 `soldiers[i]`） |
| `game.game_gui.power_1/2.cooldown_time` | 火雨 / 援军冷却，创建时取模板 `cooldown`（`user_power_1` / `re_current_1`） |
| `Power2Button.fire()` | 援军按钮入口：同步建 2 个 `re_current_*` 并 `simulation:insert_entity` |
| `e.hero.level / xp / level_stats / fn_level_up` | 英雄等级、经验、各档属性、升级函数 |
| `e.reinforcement.duration` | 援军在场时间（默认 20 秒） |
| `e.nav_rally.pos` / `e.motion.dest` | 集结点 / 移动目标（默认 0,0） |

### 模块实现要点

**金币**：`apply_gold` 每帧写 `gold_lock`、按秒累加 `gold_rate`；`kill_bonus` 给已死敌人发 `gold × kill_mult`（`KRT.counted` 去重）。

**防御塔**：`state.txt` 下发 `tw_<系>_<字段>`（`spd` / `dmg` / `rng` / `sold`），`apply_towers` 用 `FAMILY_OF[e.tower.type]` 归系，倍数自动覆盖该系全部等级与进阶。
`apply_tower` 始终以**模板原型**为基准覆写（关闭即还原、不累积），射程倍数同时放大三处：`list[i].range/range_base`、`list[i].max_track_distance`、弹药 `max_track_distance`。
伤害写共享弹药模板（`KRT.dmg_base` 缓存基准值）；`tower_mults()` 缓存解析结果避免每帧字符串拼接。

**英雄满级**：`hero.level = #level_stats.hp_max` → `hero.fn_level_up(e)` → 兜底写 `hp_max/hp`。
只补 `xp` 是不够的——游戏每次获得经验才升 1 级；`fn_level_up` 只按当前 level 写属性不改等级。

**兵营士兵数**：**模板 + 实例都写**。升级时新塔取 `ne.barrack.max_soldiers` 来自下一级模板（`sys.tower_buy` 的 `for i, s in ipairs(e.barrack.soldiers)`：`ne.barrack.max_soldiers < i` 的士兵会被就地解散），只改实例就会出现「3 个升级、其余从门里重出」。所以 `apply_barrack_templates` 把四系所有兵营模板统一写一遍，`apply_tower` 再覆盖场上实例；原始值存在 `_G.__KRT_SOLD_BASE`（弱键、跨世代保留，热重载不会把改后的值当基准），取消勾选即还原。
`tower_barrack.update` 每次循环 `for i = 1, max_soldiers`，缺人就 `create_entity(soldier_type)` 补上并写回 `b.soldiers[i]`，
所以改完几秒内士兵会陆续从门里出来；站位由 `U.rally_formation_position(i, b, max_soldiers)` 按椭圆均分。

**技能无冷却**：`power_1/2.cooldown_time = 0`（按钮 `update` 里 `phase = x / cooldown_time`，除零得 inf → 立刻 ready）。
按钮只在创建时从模板 `cooldown` 赋一次值，**写 0 后游戏不会自己还原**，所以关闭开关必须把 `cd_base` 写回去，
否则本局一直无冷却。基准值优先取首次见到的 `cooldown_time`，为 0 时查模板 `cooldown`。

**援军总数**：主路是包 `Power2Button.fire`——点一次援军按钮，先记 `edb.last_id`，调用原函数后再数 `id >= last_id` 的 `re_*`，
补 `总数 - 新建数` 个到点击点周围；与扫描/计时无关，连点也每次都补。
没有 `Power2Button`（版本差异）时退回扫 `store.entities`，已见记录用**实体对象**（弱表）而不是 id——id 会复用，按 id 记会把新兵当老面孔。
副本用 `edb:create_entity` 新建，**位置/`nav_rally.center`/`nav_rally.pos`/`motion.dest` 都设成它自己的生成点**
（模板默认 (0,0) 会往左下角跑；设成源士兵位置会叠在一起），id 撞了就换空的并推进 `edb.last_id`。
热重载时 `install_reinf_hook` 先拆上一代的包装再装新的，`attach` 每 2s 自愈。

**援军持续时间**：`apply_reinf_time` 把 `cfg.reinf_time` 写进 `reinforcement.duration`（模板 + 场上实例）。

**自动下一波**：调 `next_wave_button.on_click()`；**不能用 `store.force_next_wave`**（那是跳波）。

**游戏速度**：不改 dt，每帧补跑 `simulation:do_tick()`（`speed - 1` 次，小数累积），暂停时跳过。

**状态回传**：`status()` 每 0.4s 写 `status.txt`；游戏切界面会重建 `love.update`，故 hook `love.graphics.present`/`love.timer.step`/`love.draw` 并每 2s 自愈重包。

## 踩坑清单

1. **不要用 `QGraphicsDropShadowEffect`**：会把控件渲染进离屏 pixmap 再合成，文字重影。阴影用 `paintEvent` 自绘偏移块（`NeoCard`/`WinButton`）或 `ShadowWrap` 包装。
2. **不要用「右下边框加粗」冒充阴影**：圆角处 5px 与 3px 边接缝错位。
3. **`ShadowWrap` 的子控件不在布局里，必须 `child.show()`**；容器别设 `background:transparent`（QSS 级联会把按钮背景清掉，阴影透出变黑块）。
4. **`ta.list[i].bullet` 是模板名字符串**，要 `ents[name]` 解析后再取 `.bullet` 子表。
5. **多攻击模式的塔每条攻击自带射程**（`range`/`range_base`），漏改远目标不攻击。
6. **不放 `max_track_distance`**，炮弹远距离打不中（看起来像范围没生效）。
7. **`edb:create_entity` 的 id 可能与场上撞**，撞了插队会被忽略，要换新 id。
8. **`hero.fn_level_up(e)` 不改 level**，要先设 level 再调用。
9. **菜单里别 `edb:load()` / `create_entity`**，会崩游戏；只在关卡内测。
10. **热重载要清理旧钩子**，否则旧壳继续跑旧逻辑；壳只装一层，处理函数从 `_G` 现取。
11. **`cooldown_time` 不是每帧从模板刷新的**：只写 0 不还原，关闭开关要自己写回模板 `cooldown`。
12. **援军去重别用 id、也别用时间窗**：id 会复用、连点会被时间窗整批吞掉，两者都表现为「只出 2 个」。按点击事件补人最稳。
